# بات کانال دیجی‌هاینت — نسخه ۱

انتشار روزانه متن، کارت تصویری، مقاله و نمونه‌کار؛ بدون سرور دائمی و بدون API هوش مصنوعی.

## امکانات واقعی این نسخه

- ۲۴ آموزش متنی و ۸ کارت آموزشی فارسی آماده (۳۲ محتوای مستقل).
- خواندن ۳۰ مقاله تازه منتشرشده از وردپرس؛ استفاده از تصویر شاخص و گزیده اولین پاراگراف مناسب. این بخش خلاصه‌نویسی هوشمند نیست.
- یک نمونه‌کار اولیه رونکا؛ ساخت کارت معرفی و کشف ویدیوی MP4 صفحه پروژه در زمان اجرا.
- افزودن نمونه‌کارهای دیگر با ویرایش `data/portfolio.json`؛ این نسخه همه نمونه‌کارهای سایت را خودکار وارد نمی‌کند.
- کارت تصویری مربعی با رنگ‌های #343434 و #EFA800 و امضای متنی DigiHinet؛ لوگوی گرافیکی و فونت اختصاصی در بسته نیست.
- سه حالت preview (بدون ارسال)، test (کانال آزمایشی)، publish (کانال اصلی).
- سقف یک پست در روز برای هر کانال به وقت تهران؛ اجرای مجدد سهم روز را بیشتر نمی‌کند.
- جلوگیری از تکرار بر اساس شناسه محتوا و کانال. معرفی تصویری و معرفی ویدیویی یک پروژه دو محتوای مستقل‌اند.
- جایگزینی مقاله یا ویدیوی ناموجود با آموزش آماده؛ اتمام کامل بانک، خطا ایجاد می‌کند.
- فایل وضعیت قبل از ارسال و پس از تأیید تلگرام در گیت ثبت می‌شود. ارسال مبهم خودکار تکرار نمی‌شود.

## ۱. ساخت بات و کانال آزمایشی

1. در تلگرام وارد `@BotFather` شوید و `/newbot` بفرستید.
2. نام و username بات را انتخاب کنید؛ username باید به bot ختم شود.
3. توکن را نگه دارید؛ آن را داخل کد، Issues، فایل‌ها یا پیام عمومی نگذارید.
4. بات را در کانال `@digihinet` مدیر کنید و مجوز Post Messages بدهید.
5. یک کانال عمومی آزمایشی بسازید و همین بات را مدیر آن کنید. username آن باید با کانال اصلی متفاوت باشد.

## ۲. ساخت مخزن GitHub

1. یک مخزن Public با نام `digihinet-channel-bot` بسازید و Add a README را انتخاب کنید.
2. ZIP را روی رایانه Extract کنید. **محتویات داخل پوشه** `digihinet-channel-bot` را به ریشه مخزن منتقل کنید، نه خود پوشه را.
3. در ویندوز نمایش Hidden items را روشن کنید تا `.github` و `.gitignore` جا نمانند.
4. در GitHub از Add file → Upload files استفاده کنید و فایل‌ها و پوشه‌ها، از جمله `.github`، را بکشید و Commit changes بزنید.
5. بررسی کنید مسیر `.github/workflows/publish.yml` در مخزن وجود داشته باشد.

اگر آپلود پوشه `.github` از مرورگر انجام نشد، در مخزن Add file → Create new file بزنید، نام `.github/workflows/publish.yml` را وارد کنید و محتوای همان فایل در بسته را Paste و Commit کنید. افزودن `.gitignore` هم از همین روش ممکن است.

این بسته حدود چند ده کیلوبایت است و ویدیوها را در گیت ذخیره نمی‌کند. در مخزن عمومی متن‌های آماده و وضعیت انتشار عمومی‌اند. محتوای محرمانه داخل این فایل‌ها نگذارید.

## ۳. تعریف Secrets

Settings → Secrets and variables → Actions → Secrets → New repository secret

| Name | Value |
|---|---|
| TELEGRAM_BOT_TOKEN | توکن دریافتی از BotFather |
| TELEGRAM_CHANNEL_ID | @digihinet |
| TELEGRAM_TEST_CHANNEL_ID | @username کانال آزمایشی |

توکن را فقط در Secrets وارد کنید. شناسه کانال عمومی همان username با @ است.

## ۴. مجوز ذخیره وضعیت

Settings → Actions → General → Workflow permissions → Read and write permissions → Save.

اگر سازمان شما این تنظیم را بسته یا شاخه اصلی را محافظت کرده است، ابتدا دسترسی push بات را برای این مخزن فراهم کنید. بات باید پیش از انتشار، رزرو ارسال را روی GitHub ذخیره کند؛ در صورت خطای push هیچ پستی ارسال نمی‌کند. برای این تنظیم نیاز به ساخت PAT نیست.

## ۵. اولین پیش‌نمایش؛ بدون ارسال

Actions → DigiHinet Channel → Run workflow

- mode: preview
- kind: text

Run workflow را بزنید. بعد از سبز شدن اجرا، آن را باز کنید و از Artifacts فایل `post-preview-...` را دانلود کنید. `preview.txt` متن را دارد و `preview.json` اطلاعات محتوا را. برای نوع card یک `card.png` هم تولید می‌شود. مقاله و ویدیو در پیش‌نمایش به شکل لینک رسانه در JSON هستند، نه فایل دانلودشده.

برای اطمینان از اتصال سایت، همین کار را با kind=article و برای کارت با kind=card انجام دهید. نوع انتخاب‌شده واقعی در لاگ نوشته می‌شود؛ اگر منبع در دسترس نباشد، ممکن است آموزش متنی جایگزین شود.

## ۶. ارسال آزمایشی

دوباره Run workflow:

- mode: test
- kind: card (یا text / video / article)

این ارسال فقط به کانال آزمایشی می‌رود و سهم یا سابقه کانال اصلی را مصرف نمی‌کند. در هر روز فقط یک ارسال برای هر کانال مجاز است. برای بررسی چند نوع در همان روز از preview استفاده کنید؛ اگر عمداً می‌خواهید ارسال آزمایشی دیگری انجام دهید، فقط رکورد همان کانال آزمایشی و همان تاریخ را از `data/state.json` حذف کنید. سابقه کانال اصلی را حذف نکنید.

## ۷. روشن کردن انتشار اصلی

Settings → Secrets and variables → Actions → Variables → New repository variable

- Name: ENABLE_POSTING
- Value: true

از این لحظه برنامه روزانه فعال است. اگر ارسال فوری می‌خواهید:

Actions → DigiHinet Channel → Run workflow → mode=publish → kind=auto

**این گزینه واقعاً در کانال اصلی پست منتشر می‌کند.** پیش‌فرض اجرای دستی preview است.

برای توقف، مقدار ENABLE_POSTING را false کنید. preview و test همچنان کار می‌کنند. زمان‌بندی فعال می‌ماند ولی کانال اصلی پیام نمی‌گیرد.

## تقویم اولیه

هر روز حدود ساعت ۱۸:۱۷ تهران (۱۴:۴۷ UTC). GitHub ممکن است دیرتر اجرا کند و زمان دقیق تضمین‌شده نیست.

| روز | محتوا |
|---|---|
| شنبه | متن آموزشی |
| یکشنبه | مقاله همراه تصویر شاخص، در صورت وجود تصویر |
| دوشنبه | ویدیوی نمونه‌کار، در صورت دسترسی |
| سه‌شنبه | کارت تصویری |
| چهارشنبه | آموزش متنی |
| پنجشنبه | معرفی نمونه‌کار تصویری |
| جمعه | متن آموزشی |

کلیدهای config.json بر اساس weekday پایتون‌اند: 0 دوشنبه، 1 سه‌شنبه، 2 چهارشنبه، 3 پنجشنبه، 4 جمعه، 5 شنبه، 6 یکشنبه.

برای تغییر ساعت، cron را در فایل workflow ویرایش کنید؛ ساعت‌های این فایل UTC هستند و تهران ۳:۳۰ جلوتر است. مثال: ساعت ۱۰:۱۷ تهران = `47 6 * * *`.

## افزودن آموزش و نمونه‌کار

در `data/posts.json` رکورد جدید با id یکتا اضافه کنید:

```json
{
  "id": "tip-025",
  "type": "text",
  "title": "عنوان کوتاه",
  "body": "متن آموزش با یک اقدام مشخص برای مخاطب"
}
```

برای کارت type را card بگذارید و `card_text` کوتاه اضافه کنید. کارت باید در قاب جا شود؛ متن بیش از ظرفیت خطا می‌دهد. در GitHub هنگام ویرایش JSON، ویرگول بین رکوردها را رعایت کنید.

در `data/portfolio.json` رکوردی مانند نمونه رونکا بسازید. `url` آدرس صفحه پروژه است؛ بات MP4 داخل video/source همان صفحه را می‌خواند. برای معرفی با عکس، آدرس تصویر خودتان را در `media` بگذارید؛ اگر خالی باشد، کارت معرفی می‌سازد. `card_text` را کوتاه نگه دارید. فقط اطلاعات تأییدشده پروژه را بنویسید.

برای پست ویدیویی دستی، در posts.json رکورد با type=video و media=URL بسازید؛ برای انتخاب شدن آن باید selector را گسترش دهید یا از بانک portfolio استفاده کنید. مسیر ساده این نسخه برای ویدیو، صفحه نمونه‌کار است.

بانک اولیه محدود است؛ بات تولیدکننده نامحدود محتوای جدید نیست. متن‌های استفاده‌شده دوباره منتشر نمی‌شوند. وقتی موجودی کم شد، محتوای جدید با id جدید اضافه کنید. خبر روز و ادعاهای ابزارهای AI به صورت خودکار تولید یا بازنشر نمی‌شوند.

## خطا و بازیابی pending

بات قبل از ارسال یک رکورد `pending` ذخیره می‌کند. اگر ارسال یا ثبت نتیجه قطع شود، اجرای بعدی متوقف می‌شود تا پست ناخواسته تکرار نشود.

1. کانال مربوط به pending را باز کنید و بررسی کنید آیا پست واقعاً منتشر شده است.
2. اگر منتشر نشده، در `data/state.json` مقدار pending را null کنید و Commit کنید؛ سپس همان نوع محتوا را دوباره اجرا کنید.
3. اگر منتشر شده، رکورد pending را به انتهای sent منتقل کنید، فیلد message_id را با شماره پیام واقعی اضافه کنید و pending را null کنید. نمونه:

```json
{
  "sent": [
    {"id":"tip-001","channel":"@digihinet","date":"2026-11-01","type":"text","message_id":123}
  ],
  "pending": null
}
```

شماره پیام آخر لینک پست عمومی است؛ نمونه `https://t.me/digihinet/123`. مقدارهای واقعی id/channel/date را از pending نگه دارید؛ مثال بالا را جایگزین کل سابقه نکنید.

- 401: توکن را بررسی کنید.
- 403: دسترسی مدیریت و ارسال بات را بررسی کنید.
- 400: شناسه کانال، URL یا قالب رسانه را بررسی کنید.
- ویدیو: MP4 عمومی و قابل دریافت برای سرور تلگرام لازم است. سقف فعلی sendVideo معمولی ۵۰ مگابایت است. این نسخه URL را به تلگرام می‌دهد و تبدیل یا فشرده‌سازی ویدیو ندارد؛ اگر ویدیو رد شد pending را تعیین تکلیف و تصویر یا متن منتشر کنید.
- خطای git push: مجوز نوشتن workflow، تغییر هم‌زمان شاخه یا branch protection را بررسی کنید. برای رفع آن کل سابقه را پاک نکنید.
- خطاها در Actions مشخص‌اند؛ هشدار خصوصی جداگانه در این نسخه وجود ندارد.

## اجرای محلی

Python 3.12 و نصب requirements لازم است. پیش‌نمایش به توکن نیاز ندارد:

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python bot.py --mode preview --kind card
```

کارت به فونت DejaVuSans روی Linux نیاز دارد. در Windows متغیر محیطی FONT_PATH را به مسیر فونت فارسی TTF موجود، مانند `C:\Windows\Fonts\tahoma.ttf`، تنظیم کنید. برای استفاده اصلی، GitHub راه ساده‌تر است.

## محدودیت‌های هزینه و نگهداری

Standard Linux runner در مخزن عمومی GitHub طبق شرایط فعلی رایگان است؛ مخزن خصوصی سهمیه دارد. از Larger runner و نگهداری طولانی artifact استفاده نکنید. Bot API معمول تلگرام رایگان است. لینک‌های فایل‌های خودتان از هاست فعلی سایت مصرف ترافیک می‌کنند.

GitHub ممکن است زمان‌بندی مخزن عمومی را بعد از ۶۰ روز بی‌فعالیتی غیرفعال کند. وضعیت Actions را دوره‌ای بررسی کنید. بات در ارسال‌ها وضعیت را commit می‌کند، ولی تضمین سرویس دائمی یا انتشار دقیق سر ساعت نمی‌دهد.

این بات برای انتشار خروجی است؛ فرمان تلگرامی تعاملی و دکمه تأیید داخل تلگرام ندارد. کنترل دستی از Run workflow انجام می‌شود. نسخه پایه نظرسنجی، تولید AI، تولید ویدیو یا گزارش تحلیلی کانال ندارد.
